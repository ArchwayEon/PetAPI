# PetAPI

PetAPI is a small ASP.NET Core application for managing a list of pets. It was built as a teaching example for CSCI 3110, so the code is kept simple and commented to show how a web API is put together and how a web page consumes it.

The application has two parts:

- A **Web API** that stores pets in a SQLite database and exposes five RESTful endpoints under `/api/pets` for reading, creating, updating, and deleting pets.
- An **MVC web site** with a **Pets** page that calls the API from JavaScript with `fetch()` (AJAX).

## Features

- Get all pets
- Get one pet by id
- Add a new pet
- Update an existing pet
- Delete a pet
- A Pets page (`/Home/Pets`) that lists, shows, adds, edits, and deletes pets through the API without reloading the page
- The database is created from migrations and seeded with five sample pets

## Technology

- [.NET 10](https://dotnet.microsoft.com/) and ASP.NET Core (MVC and Web API)
- [Entity Framework Core 10](https://learn.microsoft.com/ef/core/) with the SQLite provider
- SQLite, stored in the `Data` folder
- Bootstrap and plain JavaScript modules for the web pages

## Project Layout

| Path | Purpose |
|------|---------|
| `Controllers/PetController.cs` | The API endpoints (`/api/pets`). Handles HTTP requests and responses. |
| `Controllers/HomeController.cs` | The MVC controller for the web pages (Home, Pets, Privacy, Error). |
| `Views/Home/Pets.cshtml` | The Pets page: a table of pets, an Add form, and a Details/Edit card. |
| `Views/Shared/_Layout.cshtml` | The shared page layout and navigation bar. |
| `wwwroot/js/PetRepository.js` | A JavaScript class that wraps the API with `fetch()`. |
| `wwwroot/js/pets.js` | The Pets page script. Uses `PetRepository` to call the API and updates the page. |
| `Services/IPetRepository.cs` | The interface the controller uses to read and write pets. |
| `Services/DbPetRepository.cs` | The implementation of `IPetRepository` that uses the database. |
| `Services/ApplicationDbContext.cs` | The Entity Framework database context, including the seed data. |
| `Models/Entities/Pet.cs` | The `Pet` class (`Id`, `Name`, `Weight`). |
| `Migrations/` | Database migrations generated by Entity Framework. |
| `Data/` | Location of the SQLite database file (`pet.db`). |
| `Program.cs` | Application setup: services, database connection, and routing for both the API and the MVC pages. |
| `appsettings.json` | Settings, including the database connection string. |

## Getting Started

### Prerequisites

- [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0)
- The Entity Framework command-line tool, needed only to create or apply migrations:

  ```bash
  dotnet tool install --global dotnet-ef
  ```

### 1. Restore the packages

From the project folder (the one containing `PetAPI.csproj`):

```bash
dotnet restore
```

### 2. Create the database

The repository already includes `Data/pet.db`. To create it yourself, or to bring it up to date, apply the migrations. This creates `Data/pet.db` with the `Pets` table and the five sample pets:

```bash
dotnet ef database update
```

If you delete `Data/pet.db`, run this command again to rebuild it.

### 3. Run the application

```bash
dotnet run
```

Or start it from Visual Studio, VS Code, or Rider. The `http` profile in `Properties/launchSettings.json` uses `http://localhost:5083`; the `https` profile uses `https://localhost:7158` and `http://localhost:5083`.

Then open these pages in a browser:

- `http://localhost:5083/` – the home page
- `http://localhost:5083/Home/Pets` – the Pets page that uses the API with AJAX (also linked as **Pets** in the navigation bar)

## Using the Pets Page

The Pets page loads every pet into a table when it opens. From there you can:

- Click **Details** to load one pet and fill in the Edit form.
- Change the name or weight in the Edit form and click **Save** to update the pet.
- Click **Delete** to remove a pet (you are asked to confirm first).
- Fill in the **Add a Pet** form and click **Create** to add a pet.

Each action calls the matching API endpoint through `PetRepository.js`. If a request fails, the error is shown in a red alert at the top of the page.

## Using the API

Base URL: `http://localhost:5083/api/pets`

| Method | URL | Body | Success response |
|--------|-----|------|------------------|
| GET | `/api/pets` | none | `200 OK` with an array of pets |
| GET | `/api/pets/{id}` | none | `200 OK` with one pet, or `404 Not Found` |
| POST | `/api/pets` | form-data: `Name`, `Weight` | `201 Created` with the new pet and a `Location` header pointing to it |
| PUT | `/api/pets/{id}` | form-data: `Name`, `Weight` | `204 No Content`, or `404 Not Found` |
| DELETE | `/api/pets/{id}` | none | `204 No Content`, or `404 Not Found` |

`{id}` must be a whole number. On create, any `Id` sent in the form is ignored because the database generates it. On update, the pet to change is chosen by the `{id}` in the URL.

A pet looks like this in JSON:

```json
{
  "id": 1,
  "name": "Buddy",
  "weight": 30.5
}
```

### Examples with curl (bash, zsh, macOS, Linux)

```bash
# Get all pets
curl http://localhost:5083/api/pets

# Get one pet
curl http://localhost:5083/api/pets/2

# Create a pet (form-data)
curl -X POST -F "Name=Luna" -F "Weight=6.5" http://localhost:5083/api/pets

# Update a pet (form-data; the id in the URL says which pet to change)
curl -X PUT -F "Name=Buddy" -F "Weight=31" http://localhost:5083/api/pets/1

# Delete a pet
curl -X DELETE http://localhost:5083/api/pets/3
```

### Examples with curl.exe (Windows PowerShell)

In PowerShell, `curl` is an alias for `Invoke-WebRequest`, which accepts different arguments. Type `curl.exe` to run the real curl program instead.

```powershell
# Get all pets
curl.exe http://localhost:5083/api/pets

# Get one pet
curl.exe http://localhost:5083/api/pets/2

# Create a pet (form-data)
curl.exe -X POST -F "Name=Luna" -F "Weight=6.5" http://localhost:5083/api/pets

# Update a pet (form-data; the id in the URL says which pet to change)
curl.exe -X PUT -F "Name=Buddy" -F "Weight=31" http://localhost:5083/api/pets/1

# Delete a pet
curl.exe -X DELETE http://localhost:5083/api/pets/3
```

## Changing the Database

When you change the `Pet` class or the `ApplicationDbContext`, create a new migration and apply it:

```bash
dotnet ef migrations add <MigrationName>
dotnet ef database update
```

## Troubleshooting

- **"no such table: Pets"**: the database has not been created. Run `dotnet ef database update`.
- **The Pets page shows an error or stays on "Loading..."**: make sure you opened the page from the running app (for example `http://localhost:5083/Home/Pets`), and check the browser's developer console for the failed request.
- **The pets are not the ones you expected**: your test changes are stored in `Data/pet.db`. Delete the file and run `dotnet ef database update` to start over with the sample data.
- **Port already in use**: change `applicationUrl` in `Properties/launchSettings.json`, or stop the other program that is using the port.
